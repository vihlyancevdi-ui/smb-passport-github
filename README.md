# Школа молодого бойца — РОСБИОТЕХ

Веб-приложение «Паспорт бойца»: кабинет кандидата, цифровой паспорт со штампами, миссии, события, регистрации, материалы мероприятий и административная панель.

## Архитектура

- Node.js + встроенный HTTP-сервер
- SQLite через встроенный `node:sqlite`
- фронтенд — обычные HTML/CSS/JS без отдельного build-шагa
- база данных и пользовательские материалы хранятся в каталоге `DATA_DIR`

Для публикации используем связку **GitHub → Railway**. GitHub хранит исходный код, а Railway запускает сервер и автоматически передеплоит новую версию после push в выбранную ветку. Railway поддерживает подключение GitHub-репозитория и автодеплой при новых коммитах.

## Важное про данные

`data/data.sqlite` **не хранится в GitHub**. Это сделано специально: база содержит учётные записи, прогресс кандидатов и загруженные материалы. На Railway для неё нужно подключить Volume и использовать его как `DATA_DIR`. Railway Volume предназначен для постоянных данных сервиса.

## Локальный запуск

Требуется Node.js 22.5+ (рекомендуется актуальный LTS).

```powershell
node -v
npm.cmd -v
npm.cmd run check
$env:NODE_ENV="development"
$env:ADMIN_PASSWORD="your-long-local-password"
npm.cmd start
```

Откройте `http://localhost:3000`.

Первого кандидата после входа создайте из административной панели. Тестовые пароли не зашиваются в исходный код.

## Переменные окружения

### Обязательная для production

`ADMIN_PASSWORD` — пароль первого главного администратора. Приложение не запускается без пароля длиной не менее 12 символов; сам пароль никогда не хранится в GitHub.

### Необязательные

`DATA_DIR` — каталог для SQLite. На Railway при подключённом Volume можно использовать автоматически предоставляемый `RAILWAY_VOLUME_MOUNT_PATH`; явная установка `DATA_DIR=/data` тоже допустима.


## Публикация через GitHub + Railway

1. Создайте пустой репозиторий на GitHub.
2. Загрузите в него содержимое этого проекта.
3. В Railway создайте новый Project → Deploy from GitHub repo.
4. Выберите репозиторий и ветку `main`.
5. Добавьте переменную `ADMIN_PASSWORD` со своим новым паролем.
6. Создайте Volume и подключите его к сервису с Mount Path `/data`.
7. Убедитесь, что приложение использует `DATA_DIR=/data` (либо оставьте автоматический `RAILWAY_VOLUME_MOUNT_PATH`).
8. После успешного деплоя сгенерируйте публичный домен Railway.
9. Проверьте `/health`, вход администратора, создание кандидата, миссий, штампов, событий и загрузку материалов.

После этого каждый `git push` в подключённую ветку будет запускать новый деплой.

## Безопасность

- Не добавляйте `.env`, SQLite-базу или реальные пароли в GitHub.
- Для production используйте отдельный длинный пароль администратора.
- В production cookie сессии помечается `Secure` при HTTPS.
- Healthcheck доступен по `/health`.
- База работает в WAL-режиме SQLite и находится на постоянном Volume.

## Резервное копирование

GitHub не является резервной копией базы. Для production нужно отдельно настроить резервное копирование Railway Volume / SQLite.
